# #1170 兼容性缓存写入实测

同一台 Windows，官方 DSH `0.2.2-rc.3`，独立 profile，公开目录快照与本地可控上游。快照有 10,778 个目录项，10,775 个可查标识。每轮全量查询固定 169 个 POST。应用写入字节根据应用传给文件 API 的数据统计，包含首次快照和追加。

`web-comparisons.json` 包含已完成的配对、逐项结果哈希、产物 SHA-256、CPU 和延迟数据。其余 Web JSON 包含每个 POST、并行 GET 与每次持久化的记录。两边的配对判定哈希相同。正式版是 npm `1.73.19`（`da77482`），先行版对照取自已包含 #1195 的 `3b5a8c9`。修复随后移植到 `ef14ea1`，发布候选 `dd28eb6` 的打包 SHA-256 是 `dd8364894923e13c75296403dd53aa2385b4152c15dbb14043ec1a29f0620517`。

## 第三轮 Web 与补测 Desktop

第三轮 Web 的四个场景均在同一台机器的 C: NTFS 独立 profile 上完成。冷扫应用写入从 272.54 MiB 降至 3.27 MiB，全过期重查从 549.51 MiB 降至 3.27 MiB。四组 169 个 POST，10,775 项判定哈希一致。完整 CPU、文件探针和系统物理盘观测见 [第三轮对比](ntfs-round-3-comparison.json)。

在另两组隔离 Desktop 中，首页冷读均请求 32 个 manifest；重启后的热读均为零上游请求，缓存修改时间和判定哈希不变。换回「显示全部」后两边同样观察 12 秒，新增全目录请求均为零。切换前已发出的请求分别在 594 ms 和 549 ms 后返回 200。热重启在确认缓存已落盘后进行。 [Desktop 重启和取消对照](desktop-restart-cancel-comparison.json)
